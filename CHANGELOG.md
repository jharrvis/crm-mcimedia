# Changelog

Semua perubahan penting pada CRM MCI Media dicatat di berkas ini.
Format mengikuti [Keep a Changelog](https://keepachangelog.com/id/1.1.0/).

## [Unreleased]

### Ditambahkan
- Modul Katalog Produk: CRUD produk di `/products` (pencarian nama/SKU, filter status, harga format `rupiah()`, aktif/nonaktif, hapus) + domain `app/Domains/Catalog` (model `Product` dengan scope `active()` dan urutan default `sort_order` lalu nama) + item nav "Produk" di sidebar.
- Picker produk pada form invoice (create/edit): tiap baris item punya dropdown produk aktif ("Nama — Rp harga") yang otomatis mengisi deskripsi & harga satuan; server tetap menghitung ulang total dari item yang dikirim (tidak ada `product_id` yang disimpan di `invoice_items`).
- Seeder `ProductSeeder`: 22 produk katalog awal (idempotent via `updateOrCreate` berdasarkan SKU). Dijalankan manual (`php artisan db:seed --class=ProductSeeder`) atau lewat `DatabaseSeeder` saat setup; tidak dijalankan otomatis di production.
- Halaman invoice publik via magic link (`public_token`): `GET /pay/{token}` (tanpa login, rate-limited `throttle:30,1`) menampilkan identitas usaha, nomor invoice, klien, item + total, status (lencana LUNAS bila lunas), jatuh tempo, instruksi transfer, dan unduh PDF (`GET /pay/{token}/pdf`, dokumen sama dengan route admin). Token salah/dicabut → 404; invoice dibatalkan → halaman info. Halaman tidak menampilkan data klien lain, email/WA klien, atau catatan internal.
- Konfirmasi transfer oleh klien di halaman publik (nama pengirim, nominal, tanggal, catatan opsional) → membuat baris `payments` berstatus `pending`/`bank_transfer` tanpa mengubah status invoice; validasi nominal > 0 dan ≤ total invoice, plus penolakan dobel-submit identik (nominal + tanggal sama dalam 5 menit).
- Manajemen tautan pembayaran di detail invoice admin: token 64 karakter (`Str::random(64)`) dibuat otomatis saat invoice ditandai terkirim, tombol "Salin tautan bayar"/"Buat tautan bayar", dan "Cabut tautan" (token dikosongkan).
- Verifikasi pembayaran pending di detail invoice admin: tombol "Konfirmasi" (`payments.status` → `confirmed` + `confirmed_by` + invoice `markPaid()`) dan "Tolak" (status → `rejected`, tidak mengubah status invoice, dicatat di activity log). Kolom `payments.status` adalah `varchar(16)` sehingga nilai `rejected` tidak butuh perubahan skema F2-1.
- Migrasi aditif `2026_10_02_100005_add_sender_name_to_payments_table` menambah kolom nullable `payments.sender_name` (nama pengirim dari form konfirmasi klien); migrasi F2-1 tidak diubah.
- Pengiriman invoice via email & WhatsApp (F2-5): mailable `InvoiceMailable` berisi ringkasan + tautan bayar publik (F2-4) + lampiran PDF resmi (template F2-2), dan job antrean `SendInvoiceEmailJob` / `SendInvoiceWhatsappJob` (`ShouldQueue`, koneksi `database`). Kirim pertama dari draf otomatis menandai invoice `sent`, mengisi `sent_at`, dan membuat `public_token` (mekanisme F2-4).
- Integrasi WhatsApp Fonnte: `POST` ke `https://api.fonnte.com/send` dengan header `Authorization: <FONNTE_TOKEN>` dan payload `target` (nomor 62...), `message` (ringkasan + tautan bayar), `url` (PDF publik `/pay/{token}/pdf`), `filename` (`{number}.pdf`). Konfigurasi `config/crm.php` → `fonnte.enabled`/`fonnte.token` (env `FONNTE_ENABLED`/`FONNTE_TOKEN`). Tanpa token/nomor WA/email klien, job selesai tanpa exception (skip + peringatan log, status invoice tidak berubah); email memakai konfigurasi mail Laravel standar (`MAIL_*`).
- Tombol "Kirim Email" & "Kirim WhatsApp" di detail invoice admin (tampil untuk draf/terkirim/terlambat, nonaktif + tooltip bila alamat/nomor tujuan kosong), flash hasil antre, dan panel "Riwayat pengiriman" dari `activity_logs` (event `email_sent`/`whatsapp_sent`).
- Pengingat invoice jatuh tempo (F2-6): command harian `crm:send-overdue-reminders` (terjadwal 08:30) mengirim pengingat sopan via email & WhatsApp untuk invoice berstatus `sent`/`overdue` yang jatuh tempo tepat H+1, H+7, atau H+14 (bandingkan tanggal, abaikan jam) — isi: nomor invoice, total, umur keterlambatan, dan tautan bayar publik. Pengiriman memakai jalur F2-5 (`InvoiceReminderDelivery` + `InvoiceDelivery`) dan TIDAK mengubah status invoice.
- Migrasi aditif `2026_10_02_100006_create_invoice_reminders_table` membuat tabel `invoice_reminders` (invoice_id cascade, kind `H+1`/`H+7`/`H+14`, channel `email`/`whatsapp`, sent_at) dengan unique (invoice_id, kind, channel) — satu baris per channel yang benar-benar terkirim; migrasi F2-1 tidak diubah. Idempotent: menjalankan command 2x di hari yang sama tidak menggandakan kiriman. Tanpa email/nomor WA/token Fonnte, channel itu dilewati (skip + peringatan log) tanpa exception dan tanpa baris reminder.
- Mailable `InvoiceReminderMailable` + view `emails.invoice-reminder` untuk email pengingat.
- Halaman Laporan (F2-7) di `/reports` (di balik auth, item nav "Laporan" di sidebar) dengan tiga tabel Blade tanpa paket/JS chart: (1) **Pemasukan per bulan** — total `payments` berstatus `confirmed` berdasarkan `paid_at` untuk 12 bulan terakhir, format `rupiah()`, baris bulan berjalan disorot + lencana "bulan ini"; (2) **Invoice belum lunas** — daftar invoice scope `unpaid()` (F2-1) urut `due_date` terlama lebih dulu dengan kolom nomor/klien/total/jatuh tempo/umur keterlambatan (hari), baris overdue merah + lencana "N hari lewat" (pola F2-2), tautan ke detail invoice; (3) **Ringkasan per klien** — total nilai invoice, total lunas, dan total outstanding per klien yang punya invoice, urut outstanding terbesar. Agregasi di `App\Domains\Reports\Http\Controllers\ReportController` (ringkasan per klien memakai `SUM(CASE WHEN …)` portabel SQLite/MySQL). Invoice dibatalkan dikeluarkan dari ringkasan; draf ikut dihitung sebagai nilai invoice tetapi bukan outstanding.
- Dukungan logo usaha (F2-8): key baru `crm.business.logo` (env `CRM_BUSINESS_LOGO`, path relatif terhadap `public/`, mis. `images/business-logo.png`). Bila terisi **dan filenya ada**, logo tampil di kop PDF invoice (`resources/views/invoices/pdf.blade.php`, `src` memakai path lokal absolut `public_path()` karena dompdf membaca berkas dari disk) dan di header halaman bayar publik (`resources/views/layouts/public.blade.php`, memakai `asset()`; header menggantikan kotak inisial "M" saat logo aktif). Bila kosong/path salah, kop tampil tanpa logo — tanpa error dan tanpa gambar rusak. Helper baru `business_logo_path()` (path absolut lokal) & `business_logo_url()` (URL web) di `app/Support/helpers.php`. Cara pasang didokumentasikan di `docs/DEPLOY.md`. Identitas teks lain (nama/alamat/rekening) tidak diubah.
- Multi-rekening bank (F2-9): `config/crm.php` → `crm.bank.accounts` kini berupa **daftar** rekening (bukan satu), dibaca dari env `CRM_BANK_ACCOUNTS` (JSON array `{name, account_number, account_holder}`) dengan fallback variabel tunggal lama `CRM_BANK_NAME`/`CRM_BANK_ACCOUNT_NUMBER`/`CRM_BANK_ACCOUNT_HOLDER`. Nomor rekening tidak pernah ditulis di kode. PDF invoice (`resources/views/invoices/pdf.blade.php`), halaman bayar publik (`resources/views/invoices/public.blade.php`), dan email invoice/pengingat (`emails.invoice`, `emails.invoice-reminder`) menampilkan **semua** rekening yang dikonfigurasi dengan layout rapi (kartu per rekening / blok terpisah). Helper baru `crm_bank_accounts()` (baca + normalisasi), `crm_env_bank_accounts()` (baca env), `crm_normalize_bank_accounts()` di `app/Support/helpers.php`. Daftar kosong = bagian instruksi pembayaran tampil tanpa rekening + pesan "hubungi admin" (tanpa error); entri kosong otomatis dilewati. Cara pasang didokumentasikan di `docs/DEPLOY.md` dan `.env.example`. Tanpa perubahan skema/migrasi.

- Papan kanban tugas (F3-4) di `/tasks/board` (item nav "Tugas" tetap menyorot; tombol "Papan/Daftar" untuk berpindah tampilan): empat kolom `todo → dikerjakan → review → selesai` dengan jumlah kartu per kolom, kartu memuat prioritas/klien/project/due date (merah bila lewat), dan **drag-drop antar kolom via AJAX** (`PATCH /tasks/{task}/status`, tanpa reload) — gagal simpan = kartu kembali ke kolom asal; filter pencarian judul, prioritas, klien, dan project memakai query string yang sama seperti daftar. Tampilan daftar lama tetap ada sebagai opsi (filter `f_status` kini juga bisa per status: dikerjakan/review, dan `open` berarti "belum selesai").
- Migrasi aditif `2026_10_05_100003_widen_tasks_status_column` melebarkan `tasks.status` dari varchar(8) ke varchar(16) (default tetap `open`) agar status `in_progress` muat; nilai lama `open`/`done` tetap valid. Enum `TaskStatus` bertambah `InProgress`/`Review` (label Todo/Dikerjakan/Review/Selesai + warna badge), scope `Task::open()` kini mencakup todo+dikerjakan+review (dipakai dashboard & pengingat), dan aksi `complete`/`reopen` lama tetap jalan.
- Jurnal progress project (F3-4): tabel `project_journals` (migrasi aditif `2026_10_05_100001`) berisi tanggal (`occurred_on`, bisa mundur), penulis (`user_id` dari user yang login — tidak bisa dipalsukan lewat form), kategori (`progress`/`catatan`/`hambatan`) dan isi; tampil sebagai **timeline kronologis** (terbaru dulu) di halaman detail project dengan form tambah entri, ubah inline, dan hapus. Route bersarang `projects/{project}/journals` — entri milik project lain → 404.
- Progress project otomatis + overdue (F3-4): `Project::progressPercent()` = task `done`/total (dibulatkan; tanpa task = 100% hanya bila project sudah selesai, selain itu 0%) dan `Project::isOverdue()` (deadline lewat & status baru/berjalan). Ditampilkan sebagai bar + persentase + `(selesai/total)` di **daftar** dan **detail** project, dengan lencana "Overdue" di keduanya. Perhitungan memakai `withCount`/`loadCount` sehingga tidak N+1.
- Laporan pencapaian project (F3-4): tabel `achievement_reports` (migrasi aditif `2026_10_05_100002`) menyimpan satu laporan per project per periode (minggu/bulan, unique project+tipe+rentang) berisi **ringkasan otomatis** dari data periode — task yang selesai (`completed_at` di rentang, beserta judulnya), entri jurnal (`occurred_on` di rentang, per kategori) dan jumlah hambatan — plus **narasi manual** yang tidak hilang saat laporan digenerate ulang. Halaman `/projects/{project}/reports` (buat/lihat/unduh/hapus), detail laporan dengan ringkasan+narasi, dan **unduh PDF** (dompdf, kop identitas usaha) `projects/{project}/reports/{report}/pdf`. Penyusun ringkasan dipakai bersama `App\Domains\Projects\Support\AchievementReportBuilder`.
- Command `crm:generate-achievement-reports` (`--type=week|month`, `--date=YYYY-MM-DD`, `--project=ID`) menyiapkan **generate otomatis**: membuat/menyegarkan laporan untuk setiap project yang punya aktivitas pada periode (task selesai atau jurnal), idempotent (periode sama tidak menggandakan; narasi manual dipertahankan), dan belum dijadwalkan — tinggal menambah baris scheduler bila kelak ingin otomatis. Struktur ringkasan & penyimpanan sama persis dengan generate dari UI.
- Tes F3-4 (36 tes baru, total 227 hijau): papan kanban (render 4 kolom + urutan, filter project/klien, drag-drop JSON + fallback redirect, validasi status, `completed_at` naik/turun, progress project di respons), progress & overdue, jurnal (CRUD, urutan timeline, 404 lintas project, validasi), laporan pencapaian (ringkasan dari data periode, data di luar periode diabaikan, rentang minggu Senin–Minggu, idempotensi, narasi bertahan, PDF, command + opsi `--project`, validasi tipe periode).

## [1.0.0] - 2026-10-01

Rilis pertama — live di https://crm.mcimedia.net (server sg2, Hestia,
PHP 8.3, project di `private/crm`, docroot `private/crm/public`).

### Ditambahkan
- Login admin (email + kata sandi, registrasi nonaktif) + halaman ubah kata sandi.
- Modul Klien: CRUD klien (nama usaha, kontak utama, email, WA, alamat, catatan, status aktif) + CRUD kontak tambahan per klien (nama, peran, email, WA).
- Modul Layanan: CRUD layanan per klien — jenis (domain/hosting/management server/maintenance/SEO/lainnya), nama, domain/server terkait, tanggal mulai & berakhir, harga (integer IDR), siklus (bulanan/tahunan/sekali), status aktif/nonaktif, pengingat on/off, filter klien/jenis/status + pencarian, sorotan baris overdue (merah) & ≤30 hari (kuning) dengan badge sisa hari.
- Modul Project: CRUD project per klien — judul, deskripsi, deadline, status (baru/berjalan/ditahan/selesai), nilai project (integer IDR).
- Modul Tugas: CRUD todo internal — kaitan opsional ke klien/project, prioritas (rendah/sedang/tinggi), due date, penanggung jawab, status; filter klien/project/prioritas/status/pencarian; tandai selesai/buka kembali.
- Dashboard admin: statistik klien aktif, layanan aktif, project berjalan, tugas terbuka; tabel layanan jatuh tempo ≤ 30 hari, layanan overdue, project berjalan, tugas mendesak (≤ 3 hari).
- Pengingat jatuh tempo: halaman /reminders + artisan command `crm:services-expiring` terjadwal harian 08:00 via scheduler (cron Hestia `schedule:run`).
- Audit internal: create/update/delete klien, kontak, layanan, project, tugas tercatat otomatis di `activity_logs` (siapa, apa, kapan, IP) + halaman Aktivitas.
- Struktur modular monolith: `app/Domains/{Clients,Services,Projects,Tasks,Dashboard,Core}`; uang disimpan integer IDR.
- Layout Blade + Tailwind gaya TailAdmin: sidebar, topbar, dark mode, badge pengingat di sidebar.
- CI GitHub Actions (composer install, build Vite, `php artisan test`), 37 feature test hijau.
- Seeder akun admin awal (`ADMIN_EMAIL`/`ADMIN_PASSWORD` dari environment).
